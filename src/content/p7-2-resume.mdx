# P7.2: ATS Resume Writing

Most tech companies use **Applicant Tracking Systems (ATS)** to filter resumes before a human recruiter ever sees them. If your resume is not formatted to be easily readable by these bots, you will be automatically rejected.

In this lesson, we will restructure your resume using standard single-column formats and impact-driven action formulas.

---

## 1. ATS Layout Rules

To ensure tracking systems parse your resume text correctly:
* **Single Column Only**: Avoid two-column layouts, tables, grids, text boxes, and sidebars. Bots read text top-to-bottom and left-to-right, and columns confuse them.
* **Standard Fonts**: Use clean, web-safe sans-serif fonts (like Arial, Calibri, or Inter).
* **Text Format**: Avoid saving your resume as an image. Always export it as a clean PDF or Docx containing selectable text.
* **No icons/graphics**: Remove stars, meters, and progress bars showing "skill percentages". These cannot be parsed by bots.

---

## 2. Writing Impact-Driven Bullet Points

Hiring managers want to see results, not just a list of responsibilities. Use the **Google XY-Z Formula** to write your project descriptions:

> **Google X-Y-Z Formula:**
> **Accomplished [X]**, as measured by **[Y]**, by doing **[Z]**

### Examples:
* **❌ Poor**: "Responsible for writing Express APIs and connecting them to MongoDB."
* ** Good**: "Built a secure Express task API connected to MongoDB, decreasing query latency by **24%** through the implementation of database indexing."
* **❌ Poor**: "Made the dashboard layout responsive on mobile screens."
* ** Good**: "Redesigned the curriculum layout using responsive CSS Grid, reducing mobile bounce rate by **15%** and improving accessibility scores."
