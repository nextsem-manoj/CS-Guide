---

### 1. Warning: `AdSense head tag doesn't support data-nscript attribute`
* **Affected Pages:** Home (`/`), Course Dashboard (`/course`), and Book reading layouts (e.g. `/book/p0-2-terminal`).
* **Root Cause:** In [layout.tsx](file:///c:/jbrs-landing-page/src/app/layout.tsx#L135-L140), the Google AdSense script is imported using Next.js's custom `<Script>` component:
  ```tsx
  <Script
    async
    src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-4242865347895866"
    crossOrigin="anonymous"
    strategy="afterInteractive"
  />
  ```
  Next.js automatically injects custom internal attributes (like `data-nscript`) into the script tag for script-loading and hydration tracking. The AdSense library detects this unknown attribute and emits a console warning.
* **How to Fix:** Replace the Next.js `<Script>` tag with a native HTML `<script>` tag so that Next.js leaves it unmanipulated:
  ```tsx
  <script
    async
    src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-4242865347895866"
    crossOrigin="anonymous"
  />
  ```

---

### 2. Error: `Error: no_div` in `adsbygoogle.js` (Line 188)
* **Affected Pages:** Book pages (such as `/book/p0-2-terminal`).
* **Root Cause:** This occurs because the global Google AdSense script processes a `push({})` request but cannot find any corresponding `<ins class="adsbygoogle">` element in the DOM. In [AdSenseBanner.tsx](file:///c:/jbrs-landing-page/src/components/AdSenseBanner.tsx), this is caused by two race conditions:
  
  1. **Mobile State Switch Transition:**
     * `isMobile` is initialized to `false` by default. When the component first mounts, it renders the `<ins className="adsbygoogle">` element.
     * The `useEffect` hook runs on mount and pushes to the AdSense queue: `(window.adsbygoogle = window.adsbygoogle || []).push({});`.
     * Immediately after, the hook sets a `setTimeout` to check the screen width:
       ```tsx
       setTimeout(() => {
         setIsNative(native);
         setIsMobile(window.innerWidth < 768);
       }, 0);
       ```
     * On mobile screens, this switches `isMobile` to `true`, prompting a re-render that unmounts the `<ins>` element and mounts the `<amp-ad>` (`<AmpAd>`) instead.
     * By the time `adsbygoogle.js` processes the push, the `<ins>` element is gone, resulting in the `no_div` error.
     
  2. **Ad-Blocker/Slow-Load Fallback:**
     * The banner component checks if the ad filled after `2000ms`. If the slot is empty (either because of slow connections or an ad blocker), it sets `adBlocked` to `true`:
       ```tsx
       checkTimeout = setTimeout(() => {
         if (insRef.current && insRef.current.innerHTML.trim() === "") {
           setAdBlocked(true);
         }
       }, 2000);
       ```
     * When `adBlocked` is `true`, the `<ins>` element is completely unmounted to display a custom course promo banner. If the AdSense script is still loading or attempting to fill the slot, removing the `<ins>` element causes the `no_div` error.

* **How to Fix:**
  1. **Defer the Push:** Only call `(window.adsbygoogle = window.adsbygoogle || []).push({});` *after* the client state has resolved and confirmed `isMobile` is `false`.
  2. **Prevent Unmounting:** Instead of unmounting the `<ins>` tag when `adBlocked` is `true`, keep the tag in the DOM with a style of `display: none` or wrap it without deleting it.

## 🗂️ Git = A Time Machine for Your Code

Git tracks every change you make. Think of it as **saving checkpoints** in a video game.

---

## 🔑 The 3 Zones You Must Know

```
📁 Working Directory     →   🎯 Staging Area   →   📦 Local Repo   →  ☁️  GitHub
  (your actual files)        (files ready to       (saved history)     (online backup)
                              be committed)
```

Every git command moves files between these zones.

---

## ⚡ Essential Commands — Learn These First

### 1️⃣ `git status` — Check What Changed
```bash
git status
```
> 🔍 Shows which files are modified, new, or deleted.
> Run this **before anything else** — always!

---

### 2️⃣ `git add` — Stage Your Changes
```bash
# Add one specific file
git add src/app/page.tsx

# Add everything at once
git add .
```
> 📦 Moves files from **Working Directory → Staging Area**
> The `.` means "add ALL changed files"

---

### 3️⃣ `git commit` — Save a Checkpoint
```bash
git commit -m "feat: add dark mode to homepage"
```
> 💾 Moves files from **Staging Area → Local Repo**
> The `-m` flag is your message — describe what you changed!

✅ **Good commit messages:**
- `feat: add login page`
- `fix: resolve nav bar overlap on mobile`
- `docs: update README`

❌ **Bad messages:**
- `changes`
- `update`
- `asdfgh`

---

### 4️⃣ `git log` — View History
```bash
# Full history
git log

# Short, readable version (use this one!)
git log --oneline
```
> 📜 Shows all your past commits with IDs and messages

---

### 5️⃣ `git pull` — Download Remote Changes
```bash
git pull origin main
```
> ⬇️ Fetches changes from **GitHub → Local Repo**
> Run this before starting work each day!

---

### 6️⃣ `git push` — Upload Your Changes
```bash
git push origin main
```
> ⬆️ Sends changes from **Local Repo → GitHub**
> Run this after committing to back up your work!

---

## 🔁 Your Daily Git Workflow

```bash
# 1. Start of day — get latest code
git pull origin main

# 2. Make your changes in VS Code...

# 3. Check what you changed
git status

# 4. Stage the changes
git add .

# 5. Save a checkpoint
git commit -m "feat: describe what you did"

# 6. Upload to GitHub
git push origin main
```

---

## 🌿 Branching — Work Safely Without Breaking Things

```bash
# Create & switch to a new branch
git checkout -b feature/day1-simulator

# Switch back to main
git checkout main

# Merge your branch into main
git merge feature/day1-simulator

# Delete a branch after merging
git branch -d feature/day1-simulator
```
> 🧪 Branches = a safe copy to experiment without breaking the main code

|---|---|

| Undo all unstaged changes | `git restore .` |
| Unstage a file | `git restore --staged filename.tsx` |
| See what changed in a file | `git diff filename.tsx` |
| Check remote URL | `git remote -v` |
