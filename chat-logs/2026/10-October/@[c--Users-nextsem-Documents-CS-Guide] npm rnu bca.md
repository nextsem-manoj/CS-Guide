### 🔍 How the GitHub Code Verification Works

When the student pastes their GitHub URL and clicks **`Verify & Unlock Next Lesson 🚀`**:

```
[Student pastes GitHub URL]
           │
           ▼
1. URL Parsing & Placeholder Check (Rejects generic names like "your-username", "octocat")
           │
           ▼
2. Direct Probing via GitHub Raw CDN (raw.githubusercontent.com)
   • Scans branches: 'main', 'master'
   • Looks for required day files: 'index.html', 'day1.html', 'bca-day-1/index.html', etc.
   • Fallback: Queries GitHub repository API to locate matching source files
           │
           ▼
3. Structural & Syntax Verification
   • Non-empty check: File must contain real code (> 35 characters)
   • Structure check: Valid HTML5 (doctype, html, body, head)
           │
           ▼
4. Task Requirement Verification
   • Compares code against Day {day} task regex & keywords (e.g., <h1>, <p>, <a>, etc.)
   • Verifies that the student actually wrote their own solution and did not just commit the empty starter template
           │
           ▼
5. Live Inspector Report Card
   • If Valid: Shows green checkmark, verified branch, file path, byte count, and code preview snippet. Day is unlocked!
   • If Incomplete: Shows exact list of missing tags or missing files with Git commands to push the fix.
```

### What Does "Saved Locally in Browser" Mean?

In short: **Your learning progress is saved directly inside your computer or phone's web browser storage (`localStorage`), meaning it is 100% offline-ready and loads in 0 milliseconds with zero lag.**

---

### 1. Why does it show this even though you're signed in with Google?
The platform uses a **Local-First Architecture**:

1. **Instant 0ms Loading (No Spinners or Lag):**
   * When you open the portal or click into your daily practical lesson, the app **reads your completed days and submitted code from your browser's local memory immediately**.
   * It never makes you stare at a loading spinner waiting for a slow cloud database query.

2. **100% Offline Resilience:**
   * If your internet drops or disconnects while practicing coding, you won't lose your progress. Everything stays safely stored right on your device.

3. **Background Cloud Backup:**
   * In the background, the app silently connects to **Firebase Cloud Firestore**.
   * When the cloud handshake completes, this badge updates to:  
     `☁️ Synced to Cloud (Safe & Backed Up)`
   * While the connection is idle, offline, or writing, it displays `💾 Saved Locally on Device (Offline-Ready • Instant)` so you know your work is secure right here.

---

### 2. Will you lose your progress if you close the browser?
**No, absolutely not.**
* `localStorage` is **persistent memory**. Closing your browser tabs, exiting Google Chrome, or restarting your computer does **not** erase your data.
* It remains stored on your device until you manually choose to "Clear Site Data / Clear Cookies and History" in browser settings.
* Because you are signed in with your Google Account (`nextsem.academy@gmail.com`), your progress is linked to your Google UID for cloud backup.
